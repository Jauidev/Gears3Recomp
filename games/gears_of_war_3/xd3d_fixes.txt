# What tools/find_d3d.py did not find or got wrong in Gears of War 3 (XDK 2.0.20500), checked by hand
# against GTA IV's (2.0.6274) and Gears of War's (2.0.3529, games/gears_of_war, read only).
# tools/slot.py passes it on every port; it wins over the search.
#   <name> <address>          a D3D function
#   <name> -                  none in this game (its hook is left out)
#   DeviceOffset(<n>) <m>     a device field: GTA IV keeps it at n, this game at m
#   DeviceOffset(<n>) -       none in this game: the code that uses it is left out
#
# XDK 2.0.20500 changed two signatures: SetStreamSource has no offset (device, stream, buffer,
# stride, dirty mask) and DrawIndexedVertices no base vertex (device, primitive, start index,
# index count; VGT_INDX_OFFSET is written 0). The hooks read them so (XD3D_XDK_20500).
# D3D's GPU wait turn, its hang handler and the kickoff (they do not vote on device fields):
GpuWaitCheck 82AF98D8  # one turn of D3D's GPU waits (state: device, reason, read pointer, progress tick, start tick, start timebase +20, as Gears' 8222F460); the ring-space wait 82AF59B8 in Swap spun the render thread at 94% of a core
GpuHangHandler 82B08120  # called by GpuWaitCheck after 5000 ticks without progress
KickOff 82AF5008  # the only writer of CP_RB_WPTR (0x7FC80000 + 1812)

#!votes-by-hand  (the functions below also line up the device fields: tools/find_d3d.py)

DrawVertices 82AEFF00  # DRAW_INDX auto-index (0xC0012201) after VGT_INDX_OFFSET = start vertex; UE3's RHIDrawPrimitive (8295EE10) calls it, as Gears' 827DBB10 calls 8222DA48
DrawIndexedVertices 82AF0318  # DRAW_INDX (0xC0032201); UE3's RHIDrawIndexedPrimitive (8295EE78) calls SetIndices (82AECC08) then it, as Gears' 8254F0A0 calls 8222AFD8 then 8222DE50
BeginVertices 82AEF500  # DrawPrimitiveUP: (device, primitive, vertices, stride) returns the vertex pointer; UE3 8287B3E8 copies count * stride there and ends it inline (13716 -> 48)
BeginIndexedVertices 82AEF9C0  # DrawIndexedPrimitiveUP, as Gears' 8222D4F8: (device, primitive, base vertex, vertices, indices, index format, stride, &indices, &vertices on the stack +84); UE3 8287B270 / 8287B330
SetTexture 82AEF370  # GTA 829D3728: texture slot addi 3198 (GTA 3134), fetch constant (sampler + 48) * 24
SetRenderTarget 82AECC98  # GTA 829CAB00: addi r11,r4,3172 (GTA 3108), the 0x20107 mask, 2593 / 3070 (GTA 3005)
Resolve 82AF34A8  # GTA 829CB818: (device, flags, rects, texture, point, level, slice, ..., f1 depth); render target 3172 / depth stencil 12704 for flags & 7
ClearRectangle 82AF16D8  # GTA 829D4360: (device, flags, ..., rect or a zero vector, ..., f1 depth); 0xC01C2B00 / 0xC00A2B00 packets, depth stencil 12704
Swap 82AF6B10  # GTA 829D5388: the only VdSwap caller; frame counter 16840 (GTA 16544), 24-byte copy from r4 + 28
LockResource 82AE8E40  # GTA 829D8F78: same arguments, andi. 4112, +12 / +8 by the flags
UnlockResource 82AE9140  # GTA 829D91B0: lwarx add -256, lock count 0x100
ReleaseResource 82AE93D0  # GTA 829D9338: lwarx add -1 on +4, releases the parent (+24) recursively
LockTextureRectArray 82AEE858  # GTA 829D2D18: (texture, array index, level, rect, box, flags) into the worker 82AEE798
LockTextureRect 82AEE798  # inlined: the worker both locks call (texture, array index, level, flags, ...); UE3 (8287BAF0, 8287D410, 82966208, 82966CE8) calls it itself, LockTextureRectArray (82AEE858) too (the hooks read it so: XD3D_XDK_20500)
BindVertexShader 82AF9688  # IDirect3DVertexShader9::Bind without the flags: (shader, declaration, strides, pixel shader): reads the declaration's +0x1C and the shader's +896 vfetch table (+872), as Gears' 82234D70; UE3 (829643E0) binds each shader ahead, then draws with the declaration at 12120 = 0
ADDR_NullClearColor 0x8224A840  # ClearRectangle loads its zero vector from here (lvx128) when no color is given; GTA's 0x82000BFC
